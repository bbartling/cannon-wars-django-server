🔐 Pop the Lock Tutorial


▶️ Play Pop the Lock | 🏠 Home | 🐛 Report a Bug

Pop the Lock brings the simple reflex-testing mechanic of the mobile classic into your browser. At its heart is a C routine (compiled to WebAssembly) that tracks a rotating bar on a dial and a target on its circumference. Every time you tap/click, the module checks the angular difference between the bar and the target. If you land within a small tolerance, the score increases and the bar reverses direction while the target jumps to a new position. With each successful hit, this jump becomes shorter, creating a progressively tighter and more challenging back-and-forth arc. A miss immediately ends the game; hit all required targets to win. Keeping the time-critical math in C lays a foundation for consistent timing and harder patterns as difficulty rises.

🧠 Game Logic in C and WebAssembly

The C driver implements a small state machine and exposes a minimal API to JavaScript (via cwrap). On reset, the bar starts rotating in a default direction and a random target is chosen. When you tap:

  • If the angular miss is within HIT_TOLERANCE, the score increments, the rotation direction flips, and the target “hops” along a tightening arc that starts at 180° and shrinks with each success. Speed may increase slightly to raise difficulty.
  • When you reach MAX_HITS, game_won is set.
  • Otherwise, a miss sets game_over.

Below is a representative C snippet showing the current behavior (direction reversal, tightening arc, and win/lose flags). Your actual code may differ in names or constants, but the structure mirrors the logic used in main.c. 

#include <math.h>
#include <stdbool.h>
#include <emscripten.h>

static float angle          = 0.0f;     // current bar angle (radians)
static float speed          = 2.0f;     // radians/sec, increases slightly on hit
static int   direction      = +1;       // +1 or -1, flips on hit
static float target_angle   = 0.0f;     // current target angle (radians)
static float arc_span_rad   = (float)M_PI; // starts at 180° and tightens with hits
static int   score          = 0;
static bool  game_over      = false;
static bool  game_won       = false;

#define HIT_TOLERANCE   0.15f
#define MAX_HITS        15
#define ARC_TIGHTEN     0.85f   // multiply arc after each hit (e.g., 180° → 153° → ...)
#define ARC_MIN_RAD     0.35f   // clamp so it never becomes too tiny
#define SPEED_BUMP      0.10f

static double last_ms = 0.0;

// utility: shortest angular difference in [0..pi]
static float ang_diff(float a, float b) {
  float d = fabsf(a - b);
  if (d > (float)M_PI) d = 2.0f*(float)M_PI - d;
  return d;
}

// pick a new target somewhere along the current arc in the current direction
static void choose_next_target(void) {
  // base hop center is "opposite" the last target relative to the current direction flip
  // then restrict to a shrinking arc about that center
  float center = target_angle + (float)M_PI * (float)direction;
  // wrap center to [0, 2π)
  while (center < 0) center += 2.0f*(float)M_PI;
  while (center >= 2.0f*(float)M_PI) center -= 2.0f*(float)M_PI;

  // random offset within [-arc_span/2, +arc_span/2]
  // (replace emscripten_random() with your RNG)
  float r = (float)emscripten_random();  // 0..1
  float offset = (r - 0.5f) * arc_span_rad;

  target_angle = center + offset;
  // wrap to [0, 2π)
  while (target_angle < 0) target_angle += 2.0f*(float)M_PI;
  while (target_angle >= 2.0f*(float)M_PI) target_angle -= 2.0f*(float)M_PI;
}

EMSCRIPTEN_KEEPALIVE
void reset_game(void) {
  angle        = 0.0f;
  speed        = 2.0f;
  direction    = +1;
  arc_span_rad = (float)M_PI;   // start at 180°
  score        = 0;
  game_over    = false;
  game_won     = false;
  last_ms      = emscripten_get_now();
  target_angle = 2.0f*(float)M_PI * (float)emscripten_random();
}

EMSCRIPTEN_KEEPALIVE
void step_frame(void) {
  if (game_over || game_won) return;
  double now = emscripten_get_now();
  float dt = (float)((now - last_ms) / 1000.0);
  last_ms = now;

  angle += (float)direction * speed * dt;
  // wrap angle
  if (angle < 0) angle += 2.0f*(float)M_PI;
  if (angle >= 2.0f*(float)M_PI) angle -= 2.0f*(float)M_PI;
}

EMSCRIPTEN_KEEPALIVE
void tap_event(void) {
  if (game_over || game_won) return;

  float miss = ang_diff(angle, target_angle);
  if (miss <= HIT_TOLERANCE) {
    // success: score, flip direction, tighten arc, nudge speed, hop target
    score++;
    direction = -direction;

    arc_span_rad *= ARC_TIGHTEN;
    if (arc_span_rad < ARC_MIN_RAD) arc_span_rad = ARC_MIN_RAD;

    speed += SPEED_BUMP;

    if (score >= MAX_HITS) {
      game_won = true;
      return;
    }
    choose_next_target();
  } else {
    game_over = true;
  }
}

// Minimal getters used by JS:
EMSCRIPTEN_KEEPALIVE int   getScore(void)      { return score; }
EMSCRIPTEN_KEEPALIVE int   is_game_over(void)  { return game_over ? 1 : 0; }
EMSCRIPTEN_KEEPALIVE int   is_game_won(void)   { return game_won ? 1 : 0; }
EMSCRIPTEN_KEEPALIVE float get_bar_angle(void) { return angle; }
EMSCRIPTEN_KEEPALIVE float get_target_angle(void) { return target_angle; }

🎨 Drawing & Input in JavaScript

JavaScript owns the canvas, input, audio, and UI overlays. It does not re-implement game rules. Instead, it calls the C module for authoritative state:

  • step_frame() each animation frame to advance the bar.
  • tap_event() on user click/tap.
  • Read state via getScore(), get_bar_angle(), get_target_angle(), is_game_over(), and is_game_won() to render UI and decide when to play “pop” sounds, show overlays, or restart.
// Sketch: binding to the WASM API (real file: pop_the_lock_game.js)
const stepFrame      = Module.cwrap('step_frame', 'void', []);
const tapEvent       = Module.cwrap('tap_event', 'void', []);
const getScore       = Module.cwrap('getScore', 'number', []);
const getBarAngle    = Module.cwrap('get_bar_angle', 'number', []);
const getTargetAngle = Module.cwrap('get_target_angle', 'number', []);
const isGameOver     = Module.cwrap('is_game_over', 'number', []);
const isGameWon      = Module.cwrap('is_game_won', 'number', []);

function frame() {
  stepFrame();                 // C advances time/angle internally
  const a = getBarAngle();     // authoritative bar angle
  const t = getTargetAngle();  // authoritative target angle
  // ... draw dial, bar, target, score ...
  if (isGameOver()) { /* show Game Over */ return; }
  if (isGameWon())   { /* show You Win  */ return; }
  requestAnimationFrame(frame);
}

canvas.addEventListener('click', () => {
  if (isGameOver() || isGameWon()) { /* reset handler elsewhere */ return; }
  const before = getScore();
  tapEvent();
  const after = getScore();
  if (after > before) {
    // play a “pop” sound here; direction flips are handled in C
  }
});

requestAnimationFrame(frame);

With this division of labor, rendering and audio stay smooth in JavaScript while the deterministic, difficulty-scaling logic stays in C. To extend the game, try adjusting ARC_TIGHTEN, ARC_MIN_RAD, SPEED_BUMP, or HIT_TOLERANCE, or add visual flair (trail effects, particle bursts) purely on the JS side without touching gameplay rules.
