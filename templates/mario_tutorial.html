This Mario Maker demo shows how to combine high‑performance C code with the flexibility of JavaScript. The core engine — including gravity, jumping, collision detection and simple enemy logic — is written in C and compiled to WebAssembly using Emscripten. JavaScript handles rendering on the canvas, user input, and orchestrates the camera so you get a smooth, zoomed‑in view of the action. When you use the level editor, the grid you draw lives entirely in JavaScript until you hit “Play Level”, at which point it’s serialised and handed off to the C engine via a single function call. This separation keeps the editor responsive while still benefiting from the speed of WebAssembly during gameplay.


🎨 Build Levels in the Browser

The level editor is written entirely in JavaScript. It maintains its own 2D array representing your level and updates instantly as you click and drag to place tiles. There’s no need to talk to WebAssembly until you’re ready to play. When you click the play button, the array is converted into a comma‑separated string and passed into the C function load_level(). From that point on, the WebAssembly module runs the high‑speed physics simulation, while the editor UI disappears and the game canvas takes over.
